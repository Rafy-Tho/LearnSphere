# Backend Progress

**Status:** 🟡 In progress — structure and hardening done; a few module cleanups left.

## Done

| Area | What landed |
|---|---|
| Module structure | `backend/src/` is fully module-based: `app/`, `config/`, `db/`, `common/`, `modules/` (auth, users, categories, courses, content, learning, reviews, certificates, subscriptions, admin, instructor). Legacy `controllers/`, `routes/`, `repositories/`, `validators/` removed. |
| Database migrations | `db/migrations/0001`–`0012` + `db/migrate.js` runner (`npm run db:migrate` / `db:status`) + `schema_migrations`. `0001`–`0011` applied to the live DB and verified. |
| API refactor | Response/status standardization, validators on all writes, pagination on growing lists, auth/ownership fixes, data-exposure cleanup, null semantics. |
| Endpoint naming | REST resource names across `/api/v1` (`/auth/*`, `/users/me/*`, `/admin/*`, `/courses/:courseId/*`, `/reviews/:reviewId/helpful-vote`, `/webhooks/stripe`). Frontend + admin consumers updated. |
| Naming & OOP | Kebab-case filenames, controllers/services/repositories as classes with constructor DI + default singletons, god services split, `Answer`→`Option`. |
| Security hardening | Server-side quiz grading, CSRF, helmet headers, session invalidation on password change, per-account login lockout, generic registration, audit logging, 24h idle timeout. |
| Email verification | `users.email_verified_at` + `email_verification_codes` (migration `0013`, applied). Registration and login of unverified accounts issue a hashed 6-digit code and return `requiresEmailVerification`; `POST /auth/verify-email` verifies and creates the session; `POST /auth/resend-verification-code` re-issues. Existing users verify on next login. |
| Google OAuth | `GET /auth/google` + `GET /auth/google/callback` (authorization-code + OIDC via `openid-client`: state, nonce, PKCE, ID-token validation). `user_auth_providers` (migration `0014`) links provider identities; `users.password` is now nullable for provider-only accounts. Account linking cases A–D in `modules/auth/google-oauth.service.js`; reuses the existing session service (no JWT). |
| Quiz attempts | `modules/quiz/` (migration `0015`): `quiz_attempts` + `quiz_answers`. `POST /lessons/:lessonId/quiz-attempts` grades server-side, persists the attempt + answers, and marks the lesson complete (idempotent); `GET .../quiz-attempts` returns history + best score; `GET .../quiz-attempts/latest` returns the latest completed attempt with review. Each retake inserts a new attempt. |
| Saved courses | `modules/saved-courses/` (migration `0016`): `saved_courses` join table. `POST/DELETE /courses/:courseId/saved` (idempotent, published courses only); `GET /users/me/saved-courses` (paginated, includes progress) + `GET /users/me/saved-courses/ids` for bookmark state. |
| Learning activity & XP | `modules/learning/` (migration `0017`): `user_activities` (append-only, `user_activity_type`) and `user_xp_transactions` (XP ledger, partial unique per reward). Enrollment/completion/certificate writes record activities; lesson completion is idempotent, advances `learn_progress.current_lesson_id`, awards lesson XP, and detects course completion. `POST /lessons/:lessonId/start` records start events. New `GET /users/me/activities`, `GET /users/me/xp`, `GET /users/me/xp/transactions`. `lesson_completion` dropped `time_spent_minutes`/`xp_earned`; `learn_progress.lesson_id` renamed `current_lesson_id`; `certificates` gained `confirmed_at`. |
| Billing & subscriptions | `modules/subscriptions/` split into focused repositories (plan/payment/coupon/refund/webhook-event); public `GET /plans`; checkout with server-calculated amounts + coupons (`POST /coupons/validate`); payment history (`GET /users/me/payments`, `GET /users/me/payments/:paymentId`); richer `GET /users/me/subscription`; premium gating via `subscriptionService.hasActiveSubscription`; webhook idempotency (`stripe_webhook_events`) with `checkout.session.completed`, `charge.refunded`, `refund.created/updated`; plans deactivate instead of cascade-delete. Migrations `0018`–`0019`; baseline plan seed `000_subscription_plans.sql`. |
| Billing prepaid cleanup | Aligned billing with the prepaid one-time model. Migrations `0020`–`0021`: dropped recurring columns/indexes (`cancel_at_period_end`, `cancelled_at`, `stripe_customer_id`, `stripe_subscription_id`, `stripe_invoice_id`), added `subscription_plans.features`, `stripe_webhook_events.status`, reconciled the `discount_amount` check. Removed admin payment CRUD; admin payments are read-only. Added admin coupon CRUD + redemptions, Stripe refund issuance (`POST /admin/payments/:paymentId/refunds`, partial/full, refundable-balance enforced), billing stats (`GET /admin/billing/stats`), and a read-only subscription view with an audited `/admin/subscriptions/override`. Lazy expiration now runs on read/purchase/webhook so repurchases pass `one_active_subscription_per_user`; `charge.refunded` now records refund rows. |
| Learner checkout & refunds | Migrations `0022`–`0023`: `checkout_orders` (purchase attempt before payment; snapshots plan name/duration/subtotal/discount/total/currency; one open order per purchase context), `coupon_reservations` (+`coupons.reserved_count`) for concurrency-safe redemption capacity, `refund_requests` (learner request, separate from `payment_refunds`), and payment `provider`/`payment_method`/`checkout_order_id`. New `checkout.service.js` + `checkout-order.repository.js` + `coupon-reservation.repository.js`: server-calculated pricing, 30-min order/session expiry, duplicate-checkout reuse of the open `CHECKOUT_STARTED` order, coupon reserve→finalize/release. Webhook `checkout.session.completed` now provisions from the order snapshot transactionally (legacy metadata fallback kept; delayed/retried/duplicate deliveries safe). Learner refund requests (`refund-request.repository/service/controller`, `POST/GET /users/me/.../refund-requests`) validate ownership, `paid_at + REFUND_WINDOW_DAYS` (env, default 14), and refundable balance = `amount − successful refunds`; they create a `PENDING` row only (no Stripe call, no status mutation). Payment read models expose `provider`, `payment_method`, `refundable_amount`, `refund_request_status`. Admin billing/refund workflow untouched. |
| Admin billing & refunds | Migration `0024`: `payment_refunds.idempotency_key` (partial unique), `refund_requests.payment_refund_id`, `user_subscriptions.source` (`PAID`/`ADMIN_OVERRIDE`). Central refund access rule (full refund cancels the subscription, partial keeps access until end_date; admin overrides now actually grant access via the relaxed active-subscription predicate). Admin refund-request review (`GET/POST /admin/refund-requests`, approve/reject with atomic `PENDING` transition, reviewer + note, audit), hardened Stripe refunds (payment row lock, placeholder refund row keyed by `idempotency_key`, Stripe idempotency key, idempotent replay), webhook reconciliation of placeholder rows by `metadata.idempotencyKey`, `GET /admin/refunds`, `PATCH /admin/plans/:planId/status`, plan audit events + reference-safe delete, and billing-stats `pending_refund_requests`. |
| Webhook resilience | The Stripe webhook is mounted at `/api/v1/webhooks/stripe` (before `express.json()` so the raw body is preserved). Duplicate paid orders no longer 500-loop: when a paid checkout arrives for a user who already has an ACTIVE subscription, the payment is recorded against that subscription (audit `duplicate: true`) and the duplicate order's coupon reservation is released without a second redemption. Added `npm run billing:reconcile` (`src/db/reconcile-billing.js`) + `webhookService.reconcileOrder/reconcileAll`, which fetch the Checkout Session server-side and provision only when Stripe reports `paid` — used to recover orders whose `checkout.session.completed` was missed (recovered 2 live paid orders). |

| Instructor workspace | New `modules/instructor/` (migrations `0025`–`0026`). Ownership-scoped endpoints: `GET /instructor/dashboard`, `/earnings`, `/payouts`, and `GET /instructor/courses/:courseId/{students,analytics,reviews,certificates}`; `POST /instructor/courses/:courseId/submit` moves `DRAFT`/`REJECTED` → `PENDING`. Course review workflow added to `content_status` (`PENDING`/`REJECTED`) plus `courses.submitted_at/reviewed_at/reviewed_by/rejection_reason`; admin approve/reject in `modules/courses/admin.routes.js` with instructor email notifications. `GET /admin/courses` now scopes to `instructor_id` for instructors (fixes the all-courses leak) and `/admin/dashboard` is ADMIN-only. New `platform_settings` (revenue-share %) and `instructor_payouts` with admin `GET/PATCH /admin/settings` and `GET/POST/PATCH /admin/instructor-payouts`. `schema.sql` mirrors the new enums/tables/columns for fresh installs. |
